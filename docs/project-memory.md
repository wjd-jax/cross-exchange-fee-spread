# 项目记忆

## 当前产品形态

- 项目中文名：`跨所资金费`；本地目录名保持英文：`cross-exchange-fee-spread`
- 当前优先入口是纯本地页面：`index.html`
- 不再继续维护 Flask 版本，后续界面改动只更新纯本地页面 `index.html`
- 当前核心用途是比较不同交易所永续合约资金费率差，用于做多 / 做空对冲判断

## 当前界面默认值

- 默认币种：`BTC`
- 币种输入会自动归一化：`BTCUSDT`、`BTC-USDT`、`BTC-USDT-SWAP` 会按 `BTC` 处理，避免重复拼接交易对
- 币种输入框右侧提供 `粘贴` 按钮，会读取剪贴板并复用同一套币种归一化规则写回输入框
- 默认做多交易所：`bybit`
- 默认做空交易所：`bn`（页面展示名对应 Binance）
- 默认做多市场类型：`合约`
- 默认做空市场类型：`合约`
- 默认回看：`14 天`
- 查询区间改为输入“近几天”，并提供快速选择：`24 小时`、`3 天`、`7 天`、`14 天`
- 页面会缓存上次输入的币种、交易所、市场类型、回看天数、图表颗粒度和缩放倍数
- 选择小于等于已加载区间的回看天数时，只切换本地已拉取数据视图，不重新请求交易所接口
- 手动输入超过已加载区间的回看天数时，提示用户点击“开始分析”重新拉取更长区间
- 查询区增加“互换多空交易所”快速切换按钮
- 互换按钮会同时互换“交易所 + 合约/现货”选择
- 查询区交易所控件改为两行布局：
  - 第一行是做多交易所和市场类型
  - 中间单独一行是互换按钮
  - 第三行是做空交易所和市场类型
- 每日汇总和结算明细都按倒序展示，最新数据在最上面
- 首页顶部的说明卡片已隐藏，直接展示查询表单
- 宽屏布局改为左右工作台：左侧是查询条件，右侧顶部是“分析结果 / 当前周期快照”并排主卡，下面是明细表
- 结果区视觉风格偏紧凑：更小字号、更小卡片间距、更轻的面板层级，便于继续叠加功能
- 每次页面加载后，会基于缓存配置自动触发一次分析

## 当前计算规则

- 利差定义为：`做空 funding rate - 做多 funding rate`
- 结算明细按任一边的结算时点计算
- 如果另一边该时刻没有结算，则按 `0` 计入该笔利差
- 结算明细里的“实际结算利差”只代表发生资金费结算的时点
- 当前周期快照里的资金费为交易所当前 / 下一周期预测资金费率，不代表已经实际结算
- 如果某一侧选择的是 `现货`，则该侧资金费固定按 `0` 处理
- 做多侧资费影响：
  - 资金费率为正：付资费
  - 资金费率为负：收资费
- 做空侧资费影响：
  - 资金费率为正：收资费
  - 资金费率为负：付资费

## 当前汇总展示

- 做多累计和做空累计展示的是实际持仓影响，不是原始费率简单求和
- 利差卡片展示所选区间的累计利差
- 选择周期平均收益行展示“平均日收益 + 年化”，依据是当前选中周期内的累计利差除以选中天数
- 选择周期平均收益文案会显式展示计算口径：`选择区间累计利差 ÷ 当前选择天数`
- 历史建议基于预测当日利差与历史日利差分布的对比结果给出
- 页面单独保留“当前周期快照”区块，用于和类似站点的实时口径对齐；当前以右侧主卡方式展示，按各交易所当前资费周期归一到 `8H / 天 / 年`
- 当前周期快照里的多侧 / 空侧卡片，展示的是“实际持仓影响”口径，不是交易所原始资费
- 如果某一侧是 `现货`，当前周期快照显示 `现货 · 无资金费`
- 每日汇总最后一列已合并为 `当日总利差 / 年化`
- 即使当前图表 / 明细只选择小于 14 天的视图，每日汇总默认仍展示 14 天数据
- 每日汇总统计不做内部滚动；详细结算明细与每日汇总卡片高度对齐，明细过多时在卡片内滚动
- 顶部“价差柱状图”模块作为判断历史收益连续性和未来资费位置的主要视图
- 价差柱状图支持按 `1H / 2H / 4H / 8H / 1D` 颗粒度汇总
- 价差柱状图使用红绿柱展示所选颗粒度下的区间利差，左侧 Y 轴为利差百分比
- 价差柱状图横轴按已有数据点连续排布，不因中间缺少小时数据而插入空白区段
- 价差柱状图叠加蓝色曲线展示从起点累计到当前点的累计平均年化，右侧 Y 轴文案为“累计平均年化”，刻度显示 `%/年`
- 右侧累计平均年化坐标轴优先使用覆盖满 1 天后的数据缩放，避免 1H 颗粒度下早期短样本年化极值把坐标拉歪
- 价差柱状图不展示柱顶实际结算点，保持柱子和蓝色平均收益率曲线为主
- 价差柱状图的 0 线单独高亮，每天 0 点用竖向虚线分割
- 价差柱状图的日分割标签只显示日期，不显示 `00:00`，并居中对齐当天纵向分割线
- 价差柱状图支持鼠标滚轮 / 触控板捏合缩放横轴，缩放后可左右拖动查看完整时间区间
- 鼠标悬浮到图表横坐标附近时，会自动定位到最近的数据点，不要求精确放到圆点上
- 柱状图和蓝色年化曲线共用同一个横轴数据点；悬浮卡片融合展示区间利差、累计利差、平均日收益和累计平均年化
- 当前周期快照字段使用“预测资金费率 / 8H 归一预测 / 预测日化 / 预测年化”口径
- 当前周期快照显式标注各交易所资金费结算周期
- 接口错误提示改为右下角红色小图标，悬浮后展示可复制的错误详情
- Binance Futures 直连更常见的失败原因是当前网络或 VPN 节点受限；页面对 Binance 请求做自动重试，并提示用户切换 VPN / 网络后重试
- 如果 Binance 直连仍失败，页面支持通过 URL 参数 `binance_proxy` 配置服务端代理地址；代理需要返回原始 JSON，默认以 `?url=目标地址` 形式转发
- 标签文案使用：
  - `收资费`
  - `付资费`
  - `持平`
- 总利差标签使用：
  - `盈利`
  - `亏损`
  - `持平`

## 域名与部署记忆

- 用户持有 Unstoppable Domains 域名：`wang666.nft`
- `wang666.nft` 属于 Unstoppable Web3 域名，不是传统 DNS 域名
- GitHub Pages 的标准自定义子域名需要传统 DNS 的 `CNAME` 记录，通常指向 `wjd-jax.github.io`
- 目前不要把 `app.wang666.nft`、`funding.wang666.nft` 这类二级域名配置为 GitHub Pages 自定义域名；该路径与 Web3 域名解析机制不匹配，普通浏览器访问不会稳定生效
- 如果继续使用 `wang666.nft`，可行方向是：
  - 使用 `wang666.nft` 根域名做 Web3 网站或跳转到当前 GitHub Pages 地址
  - 或使用支持传统 DNS 的域名，例如 `.com`、`.xyz`、`.net` 等，再配置二级域名访问 GitHub Pages
- 后续如果用户要求“正常浏览器稳定访问的自定义二级域名”，优先建议使用传统 DNS 域名，不继续尝试 `wang666.nft` 的二级域名接 GitHub Pages
